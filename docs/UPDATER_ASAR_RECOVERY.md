# Physical ASAR handling in Windows updates

[VERIFIED 2026-09-13] The myREWRD test box downloaded signed 2.1.0 correctly, but its active 2.0.1 process held inactive `runtime-a/resources/app.asar` open. The exclusive-open guard correctly rejected replacement. Failed-payload cleanup also touched an ASAR, leaving a partial transaction without a manifest, which blocks further automatic attempts. Windows Resource Monitor showed the TV process owning these handles. Closing the TV app released the lock; the existing native extractor then passed.

A normal ECS process reproduced the cause: Electron-patched `lstatSync(app.asar)` reports a virtual directory and caches an archive handle. A child Windows exclusive-open fails. `original-fs.lstatSync` reports the physical file and leaves exclusive-open available. Tests using `ELECTRON_RUN_AS_NODE` did not exercise that virtual filesystem.

Candidate 2.1.1 uses `original-fs` for all runtime and transaction file operations. The supervisor is explicitly unpacked and copied through its physical `app.asar.unpacked` path. Native slot/path/reparse/lock guards remain in place. A normal-Electron regression covers inactive archive access and failed payload cleanup; existing installed/package/recovery tests remain required. Version 2.1.0 is immutable and is not replaced by this change.

Attended recovery on the owner-authorized test box preserved the profile, startup, installation marker, runtime-b and the prior runtime-a. The verified signed 2.1.0 payload was moved into runtime-a while the app was stopped, startup was replaced atomically, and the same dedicated Windows user launched it. The device reported 2.1.0 at 23:48 UTC; temporary offer removal is private audit 691. YouTube TV sign-in/playback acceptance is still separate. The orphan transaction remains evidence; do not erase blockers or retry the flawed older updater blindly. Future upgrades of affected installed boxes require attended recovery or an independently validated migration path.

No backend contract, profile contents, provider credentials, device scope or fleet offer changes. This follow-up is a draft candidate until its complete Windows validation and independent review pass.
